# 관리자 가이드

## 접근 권한

- `MANAGER`: 운영 콘솔 접근과 사용자·분석 상태 조회
- `ADMIN`: 위 기능과 사용자 역할 변경, 사용자 삭제, 시스템 로그 화면

`/api/admin/**`는 `ADMIN` 또는 `MANAGER` 인증이 필요하다. 다만 Service의 세부 권한도 적용되므로 운영 콘솔 진입 권한과 모든 변경 권한이 동일하지는 않다.

## 제공 기능

| 기능 | 실제 구현 |
|---|---|
| 사용자 목록 | 페이지 조회 |
| 역할 변경 | `ADMIN`만 가능 |
| 사용자 삭제 | `ADMIN`만 가능, 보호 역할 제한 적용 |
| 분석 작업 목록 | 상태 필터와 페이지 조회 |
| 분석 삭제 | 공통 리포트 삭제 Service 사용, `ADMIN`은 소유권 검사 생략 |
| health | backend는 실제 `UP`, 분석 엔진 표시는 현재 `MOCK` |
| 시스템 로그 화면 | 프론트 상수 기반 mock 데이터 |

관리자 분석 삭제도 `DONE`, `FAILED`, `CANCELED`만 허용한다. `QUEUED`, `PROCESSING`, `CANCEL_REQUESTED` 강제 삭제는 미구현이다. 파일이 이미 없으면 경고 로그를 남기고 DB 삭제는 계속한다.

`MANAGER`의 임의 사용자 분석 삭제는 현재 Service에서 관리자 소유권 생략 대상으로 처리되지 않는다. 전체 사용자 분석 삭제가 필요한 운영자는 `ADMIN` 역할을 사용한다.

## 운영 점검

1. Compose `ps`와 각 서비스 로그를 확인한다.
2. 실패 job의 안전한 오류 메시지와 원본 존재 여부를 확인한다.
3. 재시도 전 외부 엔진 및 storage mount를 점검한다.
4. 삭제 전에 상태와 대상 job을 재확인한다.
5. 개인정보, token, API key, 절대 영상 경로를 화면 공유나 로그 전달에 포함하지 않는다.

실제 서버 로그는 `docker compose logs`로 확인한다. 현재 시스템 로그 UI를 감사 로그 저장소로 간주하면 안 된다.
