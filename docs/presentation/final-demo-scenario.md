# 최종 시연 시나리오

## 목표와 시간

5~7분 동안 새 영상의 업로드·상태 흐름과 기존 완료 리포트의 분석 품질을 함께 보여준다. 실제 분석은 길어질 수 있으므로 새 분석을 기다리는 동안 미리 준비한 개인정보 없는 `DONE` 리포트를 사용한다.

## 사전 준비

- Docker 서비스와 공유 storage mount 확인
- 개인정보 없는 시연 계정·영상·완료 리포트 준비
- Ollama 모델 상태 확인
- NVIDIA 사용 리포트의 `actualProvider=NVIDIA_NIM`, 모델, `fallbackUsed=false` 확인
- 백업 생성과 기존 데이터 보존 확인

## 진행

1. **서비스 소개**: 피치메이트와 5개 정량 항목을 설명한다.
2. **로그인**: 사용자별 영상·리포트 소유권을 설명한다.
3. **촬영 안내**: 얼굴, 상반신, 양손, 조명과 카메라 고정 조건을 보여준다.
4. **새 분석**: 영상을 선택하고 업로드하면 자동으로 `QUEUED` job이 생성되는 흐름을 보여준다.
5. **상태**: `PROCESSING` polling과 분석 중단, `CANCEL_REQUESTED` 의미를 설명한다.
6. **기존 리포트**: 보관함에서 최신 완료 리포트를 연다.
7. **점수**: 종합 점수와 자세·표정·시선 처리·음성·제스처를 설명한다.
8. **신뢰도**: 낮은 감지 신뢰도 경고와 접힌 상세 분석 지표를 보여준다.
9. **피드백**: level 기준 강점·개선 필요 카드와 timestamp 이동을 확인한다.
10. **한국어 코칭**: qwen3:4b 최종 피드백과 예상 질문을 확인한다.
11. **복구 정책**: 실패·취소 job은 동일 `jobId`로 재분석하고 완료·실패·취소만 삭제함을 설명한다.
12. **아키텍처**: Spring Boot, 두 FastAPI 엔진, MySQL, 공유 storage, Nginx의 책임을 요약한다.

## 운영자 시연

운영 콘솔에서는 사용자와 분석 작업 상태를 조회한다. 역할 변경과 사용자 삭제는 `ADMIN`만 가능하다. 시스템 로그 화면과 분석 엔진 health 표시는 현재 mock이므로 실제 기능처럼 설명하지 않는다.

## 장애 대비

- 신규 분석이 끝나지 않으면 준비된 결과로 즉시 전환한다.
- NVIDIA 장애 시 Ollama 또는 결정적 fallback으로 완료되는 구조를 설명한다.
- 실제 NVIDIA 신규 호출은 비용이 발생할 수 있으므로 시연 전 승인과 quota를 확인한다.
- DB 볼륨 삭제나 사용자 데이터 정리는 시연 중 수행하지 않는다.

상세 체크는 [최종 시연 체크리스트](pre-demo-checklist.md)를 따른다.
