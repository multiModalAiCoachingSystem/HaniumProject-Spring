# 실제 영상 시각 분석 회귀 테스트

## 목적

FaceMesh, MediaPipe Pose, 시선 및 제스처 분석이 실제 영상에서 동작하는지 반복 측정한다.
점수 가중치나 기준식을 조정하는 테스트가 아니라 입력 영상 처리, landmark 검출, fallback 여부와
동일 입력 재현성을 확인하는 테스트다.

## 보안 및 샘플 관리

- 원본 파일명, 사용자 식별 정보, 절대 저장 경로는 기록하지 않는다.
- 회귀 샘플은 Git 작업 트리 밖의 공용 스토리지에 보관한다.
- 원본을 직접 편집하지 않고 20초 길이의 파생 복제본만 사용한다.
- 샘플과 측정 JSON은 Git에 추가하지 않는다.
- 보고서와 로그에는 샘플 별칭 A~E만 사용한다.

## 샘플 구성

| 별칭 | 컨테이너 | 해상도 | FPS | 길이 | 조건 |
|---|---|---:|---:|---:|---|
| A | MP4 | 1280×720 | 29.943 | 약 20초 | 원근 장면과 얼굴 클로즈업이 섞인 무대 영상 |
| B | MP4 | 1280×720 | 59.940 | 약 20초 | 밝은 실내, 화면 가장자리의 작은 측면 얼굴 |
| C | MP4 | 1280×720 | 29.943 | 약 20초 | 상반신과 양손 제스처가 보이는 무대 영상 |
| D | MP4 | 794×720 | 29.943 | 약 20초 | 저조도 및 부분 크롭 |
| E | MOV | 인코딩 720×1280 | 59.940 | 약 20초 | 회전 메타데이터 90도가 있는 MOV |

모든 샘플은 OpenCV에서 열렸고 첫 프레임 읽기에 성공했다. E는 표시 방향이 정상이 되려면
컨테이너가 회전 메타데이터를 적용해야 하는 샘플이다.

## 측정 방법

`analysis-engine/scripts/vision_regression.py`를 Analysis Engine 컨테이너의 `/app/scripts`에 복사한 뒤
각 샘플을 `LABEL=/app/storage/...` 형식으로 지정한다. 같은 측정을 최소 두 번 실행하고, 실행 사이에
`analyze_vision_metrics` 캐시를 비워 실제 프레임을 다시 읽는다.

측정 항목:

- 프레임 읽기 시도/성공/실패 수
- FaceMesh 전체 프레임 및 crop retry 검출 수
- `faceDetectionRatio`와 얼굴 영역 비율 최소/평균/최대
- `gazeDetectionRatio`, `eyeContactRatio`
- `gestureVisibleRatio`, 유효 프레임 수, 활동 점수와 fallback 사유
- 자세, 표정, 시선, 제스처 및 종합 점수
- 영상 회전 메타데이터와 OpenCV 자동 방향 보정 적용 여부

## 확인된 원인

| 분류 | 근거 | 처리 |
|---|---|---|
| 비연속 프레임과 tracking 모드 불일치 | 분석기가 약 0.5초 간격으로 seek하지만 FaceMesh가 tracking 모드였음 | FaceMesh를 `static_image_mode=True`로 변경 |
| `FACE_TOO_SMALL` | B/E는 밝고 모든 프레임을 읽었지만 정면 얼굴 검출과 crop retry가 모두 0건 | 현재 알려진 한계로 유지 |
| `PROFILE_FACE_LIMITATION` | B/E 발표자는 화면 가장자리에서 측면을 향함 | 현재 알려진 한계로 유지 |
| `LOW_LIGHT`/부분 크롭 | D는 얼굴 영역이 충분한 구간도 있으나 검출률이 0.209 | confidence cap과 사용자 신뢰도 경고 유지 |
| `ROTATION_METADATA` | E는 OpenCV 자동 방향 보정이 꺼져 원시 세로 프레임으로 분석됨 | vision/gesture `VideoCapture`에서 자동 방향 보정 활성화 |
| `GAZE_DEPENDENCY` | 시선은 FaceMesh가 검출된 프레임에서만 계산 가능 | 낮은 얼굴 검출률에서는 기존 confidence cap 유지 |

현재 공용 스토리지 마운트와 경로 해석은 정상이다. 모든 샘플에서 프레임 읽기 실패는 0건이었고,
제스처 분석의 `video_file_missing` fallback은 재현되지 않았다.

## 합격 기준

- 같은 샘플을 두 번 분석했을 때 raw metrics와 점수가 동일하거나 허용 오차 안에 있어야 한다.
- 읽기 가능한 영상에서 `video_file_missing` fallback이 발생하지 않아야 한다.
- 회전 메타데이터가 있는 영상은 정방향 프레임으로 vision과 gesture를 분석해야 한다.
- 얼굴이 검출된 영상은 얼굴 영역 비율과 face/gaze 원시 지표를 반환해야 한다.
- 낮은 얼굴 검출률을 임의의 높은 점수로 보정하지 않아야 한다.
- pose, expression, gaze, gesture 및 기존 점수 가중치는 변경하지 않는다.

이번 측정에서는 모든 샘플이 두 번의 실행에서 동일한 metrics와 scores를 반환했다.

## 알려진 한계

- 화면 면적의 약 1%보다 훨씬 작은 얼굴과 측면 얼굴은 현재 FaceMesh 및 정면 Haar crop retry로
  검출하지 못할 수 있다.
- 표정과 시선은 FaceMesh 검출에 의존하므로 작은 얼굴에서는 confidence fallback 또는 점수 상한이
  적용된다.
- 저조도, 부분 얼굴, 강한 역광은 얼굴 검출률을 낮출 수 있다.
- 이번 단계에서는 새 얼굴 detector, MediaPipe Tasks API, 점수 가중치 변경을 도입하지 않았다.

장기 개선 후보는 촬영 품질 경고, 최소 얼굴 크기 안내, 측면 얼굴을 지원하는 detector 검토다.
